# QuakeShield Frontend

React/Vite dashboard for the **QuakeShield Hazard Intelligence** prototype.

The dashboard presents historical earthquake scenarios together with separate secondary-hazard model indicators, verified spatial evidence, infrastructure context, and human-review guidance.

---

## What the Dashboard Shows

For each historical earthquake scenario, the dashboard can display:

* Earthquake location
* Date
* Magnitude
* Depth
* P1 Ground-Failure model indicator
* P2 Liquefaction model indicator
* Spatial evidence availability
* Verified spatial anchors
* Historical liquefaction evidence
* ShakeMap PGA context
* Mapped infrastructure context
* Review guidance
* Scenario explanation

The dashboard is designed for **human review and decision support**.

---

## Important: What It Does Not Do

The current frontend does **not**:

* Predict future earthquakes
* Provide real-time earthquake detection
* Generate a single overall risk score
* Display HIGH/MEDIUM/LOW risk classifications
* Issue automatic alerts
* Confirm infrastructure damage
* Estimate infrastructure vulnerability
* Predict casualties or economic loss
* Provide evacuation instructions

The current prototype works with **historical earthquake scenarios**.

## Dashboard Architecture

```text
Historical Earthquake Scenario
             │
             ├───────────────┐
             │               │
             ▼               ▼
      P1 Ground Failure   P2 Liquefaction
          Indicator           Indicator
             │               │
             └───────┬───────┘
                     │
                     ▼
              Spatial Evidence
                     │
                     ▼
          Infrastructure Context
                     │
                     ▼
              Human Review
```

The dashboard intentionally keeps the two hazard indicators separate.

There is no primary combined risk score.

---

## P1 — Ground Failure

The frontend displays the production P1 model indicator generated by:

```text
models/p1_ground_failure_model_slope_pga.joblib
```

The production P1 model uses:

* Slope
* ShakeMap PGA

The displayed value is a **model score**, not a calibrated probability.

---

## P2 — Liquefaction

The frontend displays the production P2 liquefaction model indicator.

The underlying model uses geotechnical and earthquake-related variables such as:

* Magnitude
* PGA
* Depth
* `(N1)60`
* `qt1N`
* `Ic`
* `VS1`
* Fines content
* Effective stress information

The P2 score is an **uncalibrated model indicator**.

It should not be interpreted as a guaranteed event-level probability.

---

## Spatial Evidence

Spatial evidence is available for selected historical scenarios.

The dashboard can display:

* Number of verified spatial anchors
* Historical record count
* Historical liquefaction outcome rate
* Mean historical PGA
* Mean current ShakeMap PGA

Currently verified scenarios include:

* Tohoku-Oki
* Kobe
* Niigata-Chuetsu

Spatial evidence is displayed as **supporting historical and ground-motion context**.

It is not converted into a single spatial risk score.

---

## Infrastructure Context

The dashboard can display mapped infrastructure categories such as:

* Hospitals
* Schools
* Bridges
* Roads

The infrastructure information represents geographic context around a representative scenario location.

It does not indicate confirmed exposure, vulnerability, or damage.

A zero mapped count means that the query returned no mapped feature for that category. It does not prove that the feature is absent from the real world.

---

## Human Review

The dashboard is designed around a human-in-the-loop workflow.

The system presents:

```text
Model Indicators
       +
Spatial Evidence
       +
Infrastructure Context
       +
Scenario Explanation
       ↓
Human Review
```

The reviewer remains responsible for interpreting the available evidence.

---

## Data Source

The frontend receives scenario information from:

```text
src/scenarioData.js
```

The data includes:

* Scenario metadata
* P1 score
* P2 score
* Spatial evidence fields
* Infrastructure fields
* Review context
* Explanation text

The frontend does not independently train or validate the machine-learning models.

## Running the Frontend

Install dependencies:

```bash
npm install
```

Start the development server:

```bash
npm run dev
```

The Vite development server will provide the local dashboard URL.

---

## Production Build

Create a production build with:

```bash
npm run build
```

A successful build should produce the `dist/` directory.

## Future Extensions

The frontend architecture can later be extended to support:

### Dynamic Post-Earthquake Intelligence

* Real earthquake feeds
* Post-event environmental data
* Satellite/change detection
* Soil/moisture information
* Rainfall/weather context
* Ground/seismic observations
* Dynamic reassessment

### Authority Decision Support

* Evidence review workflow
* Authority verification
* Approve/reject actions
* More detailed infrastructure context
* Supporting evidence visualization

### Public Precaution System

* Authority-approved alerts
* Location-specific precautions
* Official-information integration
* Individual notifications
* False-positive and false-negative safeguards

These are **future capabilities** and are not represented as currently implemented functionality.

## Disclaimer

QuakeShield is a research/prototype decision-support system.

The dashboard should not be used as a substitute for official earthquake information, engineering assessment, emergency-management procedures, or decisions made by qualified authorities.
